The exact sum is 2. Ordinary floating-point addition rounds after every step, so the order of a reduction changes its result, and a parallel reduction's order changes with the thread count. A correctly rounded sum has one answer.

Why

Correctly rounded functions give one right answer, so they agree everywhere; crmvec does that for the vector functions compilers call. But most differences between machines come from elsewhere: the order of a sum, fast approximations inside larger operations, formats with no standard math library, and tools that can't tell you where a difference comes from. The libraries here close those gaps one at a time.

What is in it

crsum

Correctly rounded sums, dot products and matrix products in binary64 and binary32, in all four rounding modes: the same bits in any order, split or thread count. crgemm_oz gives exact matrix products through any binary64 BLAS you already have (the Ozaki scheme).

For simulation, training and inference, finance: anyone who needs a reduction to come out the same twice.

crnn

sigmoid, silu, gelu, softplus and rsqrt correctly rounded in binary32, binary16 and bfloat16, and logsumexp, softmax, layernorm and rmsnorm specified bit for bit on top of crsum. Neither a rounding mode nor -ffast-math's flush-to-zero changes a result.

For inference and training that must give the same output on every machine.

lowp

Correctly rounded math for the OCP 8-bit formats (E4M3, E5M2) and OCP MX blocks (MXFP8, MXFP6, MXFP4, MXINT8): the 41 functions CORE-MATH has for binary16, proven on every input or correct by construction.

For low-precision machine learning, and hardware and emulator writers.

ival

The tightest binary64 interval enclosures of 32 elementary functions, and of atan2, hypot and pow on boxes.

For verified and interval computing.

repro-scan, repro-diff

What in a binary or a build makes its results machine-dependent; and a program run under changed conditions (threads, flush-to-zero, an older CPU) with its output compared.

For anyone chasing a result that changes between machines.

the checking kit

Number formats down to FP4, correctly rounded references through MPFR, and runs with controls and verdicts.

For building checks like these.

How it is checked

Each library is checked against answers it did not make, with controls that must fail, and with deliberately planted bugs that the checks must catch. Every check ends in one verdict line:

IDENTICAL · exit 0DIFFERS · exit 1VOID · exit 2

VOID means nothing was tested: a control did not fail, or the check could not run. CI runs every check on x86-64 and natively on arm64.

Build and check

make          # the kit, lowp, ival, crsum, and their checks
make check    # every check: the kit, repro-scan, lowp, lowp's MX, ival, crsum, crnn

Needs gcc 13 or later (for _Float16 and __bf16), MPFR 4.2 or later, and OpenMP. repro-scan needs Python 3 and binutils.
